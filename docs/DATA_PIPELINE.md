# Data pipeline

## Included corpus

`data/manifest.json` records nine reviewed, local sources with source/version,
license evidence, rights attestation, attribution, content SHA-256, quality and
quarantine fields. `scripts/prepare_corpus.py` assembles them into
`artifacts/data/corpus.txt` (102,879 bytes, SHA-256
`97a20dc524825f488f9c5df6c203f6bad4e3af827039491e643fc0b5764ead69`). See
[provenance](PROVENANCE.md) for source licenses and notices.

`helix.data.build_from_corpus` splits on blank-line-delimited documents **before**
training the BPE tokenizer, then adds a reserved EOS after every document and
writes memory-mapped token arrays. The included split contains 462 training and
52 validation chunks, with 49,849 and 2,512 tokens respectively. It is an
ordered paragraph/document split, not an independent source-level holdout;
related material can occur on both sides. The tokenizer is fitted on training
only. Metadata records the corpus and generated-file hashes, split and vocabulary
target. Training rejects mismatched recorded data, corpus, split or vocabulary.
Older custom prepared data without metadata produce a warning, not a guarantee.

The SFT dataset is `data/sft_pairs.json`, 48 HELIX-authored instruction/response
pairs (44 training, 4 held out). It is not a large or independent instruction
benchmark. The vision, caption and image-generation data are generated by the
HELIX renderer; their manifests contain seeds and pixel/caption hashes.

## Discovery and ingestion

- `helix corpus-search` searches GitHub repository metadata; every hit remains
  quarantined. It does not download data or infer file-level rights.
- `helix corpus-scan` accepts local files and records explicit user-supplied
  rights/license evidence; unknown rights, invalid extraction, exact duplicates,
  simple 5-word-Jaccard near duplicates and specified benchmark strings are
  quarantined. `helix corpus-build` verifies the recorded hash before writing a
  training corpus. Attestations are not automated legal review.
- Text, common source-code formats, HTML, notebooks, bounded EPUB archives and
  text PDFs (optional `pypdf`) have basic extraction. Scanned PDFs/images require
  OCR and are quarantined. EPUB reading is a simple sorted-HTML extraction, not
  full semantic book reconstruction. There is no malware scanner, semantic
  deduplication, comprehensive language identification, contradiction tracking,
  automated attribution or crawling of external websites.
- The image manifest path requires a local file, SHA-256, caption, license and
  explicit rights/safety review. It filters exact hashes and an approximate
  average-hash duplicate heuristic. Rights and safety are human attestations,
  not automated content judgments.

The starter build checks a small, explicitly listed set of evaluation strings;
this is **not exhaustive benchmark decontamination**. The original diagnostic
probes are too small to establish generalization. Review sources and legal terms
before expanding data or distributing derivative artifacts. Paths in the
included manifest are relative to the repository root; local scan IDs can vary
with checkout path.
