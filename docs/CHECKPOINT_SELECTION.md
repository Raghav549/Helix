# Chat checkpoint selection

Every training run evaluates both the base checkpoint and the instruction-tuned checkpoint using the same held-out token windows and the same small diagnostic task suite. The selector chooses SFT when it passes more diagnostic tasks. If task scores tie, it chooses SFT when its held-out language-model loss is lower, or when the SFT instruction holdout loss improves by at least 20% and the language-model validation-loss regression is no more than 1.5. Otherwise, it keeps the base checkpoint. These thresholds are explicit engineering guardrails for this tiny prototype, not universal research constants. The selected stage, both score summaries, the reason, and the exact task list are recorded in `checkpoint-selection.json` and embedded in the model bundle.

This prevents a reduction in SFT-pair loss from being treated as proof of improved general capability. It is still only a small diagnostic suite: neither a tie nor a pass-rate improvement proves broad intelligence, factual coverage, or real-world reliability. Both base and SFT reports remain attached to each release so the decision can be audited.
